# Evolution of Agentic Engineering — v0.2 conceptual model

Status: proposed conceptual correction

This document defines the meaning of v0.2 before changing claims, evidence mappings, schemas, generated evaluation, or public site surfaces.

## Why v0.2

v0.1 represented the evolutionary sequence as:

> Apparition → Mutation → Selection → Cooperation → Specialization

That representation treated Mutation as an independent stage.

Re-reading Daniel San Martín Sepúlveda's model shows a more precise structure. Selection acts on **versions of the object**. Variation must therefore already exist for Selection to occur. Mutation is the mechanism that produces those versions after an object appears; it is not a separate stage that the object enters and leaves.

v0.2 corrects that translation while preserving v0.1 as research history.

## Evolutionary structure

The stages are:

> **Apparition → Selection → Cooperation → Specialization**

Mutation / variation is an evolutionary mechanism operating once an object has appeared.

```text
APPARITION
object appears
    │
    ├── variation / mutation
    ├── version A
    ├── version B
    └── version C
             │
             ▼
         SELECTION
  environment filters versions
         by relative fitness
             │
             ▼
        COOPERATION
 fit objects cooperate in ways
 that improve their persistence
             │
             ▼
      SPECIALIZATION
 persistent cooperation produces
 differentiated responsibilities
             │
             ▼
      HIGHER-ORDER OBJECT
```

The higher-order object can itself become the object of another evolutionary cycle. The model is therefore potentially recursive rather than a terminal maturity ladder.

## 1. Apparition — the object comes into existence

Apparition occurs when previously separate pieces interact in a pattern that produces a new object.

Applied to agentic engineering, the object is not merely a language model or an interactive coding assistant. An agentic engineering actor appears when components such as model, context, tools, execution, permissions, and feedback combine into an object capable of meaningful engineering action.

Once the object exists, different versions can arise. Differences in models, tools, context strategies, permissions, harnesses, subagents, orchestration, and operating patterns are therefore **variation among appeared objects**.

### Role of mutation

Mutation is not an independent evolutionary stage.

It is the mechanism that generates variation in the appeared object. This variation supplies the alternatives on which Selection can operate.

Evidence of proliferating coding-agent configurations should therefore not be interpreted as evidence that agentic engineering has entered or completed a discrete Mutation stage.

## 2. Selection — the environment filters versions

Selection presupposes multiple versions of the object. Versions better adapted to their environment are more likely to persist.

Conceptually:

```text
object + variation + environmental pressure → selection
```

Applied to agentic engineering, the working hypothesis is that increasing variation among viable agentic engineering objects is encountering engineering environments that materially determine which configurations can operate reliably and economically at scale.

Candidate DevEx conditions — Context, Execution, Verification, Coordination, Observability, Economics, and Learning — represent possible properties of that engineering environment. They are not evolutionary stages. They are candidate sources of selection pressure.

The 1K-agent forcing function amplifies those pressures. It is a stress test for environmental fitness, not a prediction or adoption target.

### v0.2 working hypothesis

> **Agentic engineering may be entering Selection as increasing variation among viable agentic engineering objects encounters engineering environments that determine which configurations can operate reliably and economically at scale.**

## 3. Cooperation — cooperation improves persistence

Cooperation is more than the existence of multi-agent workflows.

In the evolutionary model, multiple instances of the object cooperate in ways that increase their probability of persisting over time.

For agentic engineering, orchestration, delegation, shared state, human-agent collaboration, and capability composition may be manifestations of Cooperation, but their existence alone does not establish the evolutionary claim.

The stronger research question is:

> Does cooperation make the agentic engineering object more capable of succeeding or persisting than isolated versions of the object?

## 4. Specialization — persistent cooperation produces a higher-order object

Specialization is more than assigning specialized roles to agents.

It emerges when differentiated objects participate in persistent cooperation and the cooperating group becomes sufficiently integrated that the group itself constitutes an object at a higher level of complexity.

Applied to agentic engineering, the meaningful object may therefore shift from an individual coding agent to an agentic engineering capability or system composed of differentiated cooperating parts.

A specialized agent is not by itself evidence of this transition. Evidence should establish persistent cooperation, differentiation, and formation of a durable higher-order capability.

## What changed from v0.1

| v0.1 | v0.2 |
| --- | --- |
| Mutation represented as an independent stage | Mutation/variation represented as a mechanism |
| Five-stage sequence | Four-stage evolutionary sequence |
| Agent diversity could be read as evidence of a Mutation stage | Agent diversity supplies the versions required for Selection |
| Selection primarily framed as environments determining what scales | Selection explicitly framed as environmental filtering among variants |
| Cooperation primarily framed as composition into complex workflows | Cooperation asks whether cooperation improves fitness/persistence |
| Specialization primarily framed as stable differentiated capabilities | Specialization requires persistent cooperation and formation of a higher-order object |
| Model could read as a linear maturity ladder | Higher-order objects can potentially begin another evolutionary cycle |

## Research consequence

The v0.1 evaluation state `C02 / Mutation — UNOBSERVED` should not automatically trigger a search for more evidence of a discrete Mutation stage.

Instead, it exposed a problem in the translation of the source evolutionary model: the research system was asking evidence to establish a stage that the underlying model does not require.

This is a model refinement, not a retroactive rewrite. v0.1 remains part of the research provenance.

## Boundary of this proposal
