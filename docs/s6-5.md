# S6.5 — Preview Evidence Environment

## Purpose

Make contribution previews query the evidence projection produced from the contribution itself, without allowing branch work to mutate production D1.

## Invariant

GitHub YAML remains canonical. D1 remains a disposable projection.

- `main` projects canonical evidence into the production D1 database.
- Pull requests that change the evidence projection project their branch corpus into a shared preview D1 database.
- Cloudflare Pages production binds `EVIDENCE_DB` to production D1.
- Cloudflare Pages preview binds `EVIDENCE_DB` to preview D1.
- Neither database identity nor database UUID is committed to `wrangler.jsonc`.

## Configuration boundary

`wrangler.jsonc` contains only application-level Wrangler metadata. Remote database selection belongs to deployment environments:

- Cloudflare Pages owns the runtime `EVIDENCE_DB` binding separately for Production and Preview.
- GitHub environment `production` provides `EVIDENCE_DB_NAME`, `CLOUDFLARE_ACCOUNT_ID`, and `CLOUDFLARE_API_TOKEN` to the production synchronization workflow.
- GitHub environment `preview` provides the same names, with `EVIDENCE_DB_NAME` selecting the preview database.

The Cloudflare credentials remain secrets. `EVIDENCE_DB_NAME` is an environment variable because a database name is configuration, not a credential.

## Shared preview semantics

S6.5 deliberately uses one shared preview database. The latest qualifying pull-request synchronization owns its contents. The workflow uses a single concurrency group and cancels an older preview synchronization when a newer one starts.

This is sufficient while contribution concurrency is low. If simultaneous independent preview state becomes necessary, the next step is per-PR D1 lifecycle management rather than adding branch-specific database identities to source control.

## Admission boundary

Preview synchronization does not incorporate evidence into the research corpus. Incorporation still occurs only when the contribution reaches `main`; the production synchronization workflow then rebuilds the production projection from canonical evidence.
