# S3 — Deterministic evidence indexer

## Goal

Turn the S2 projection contract into a functioning, deterministic rebuild pipeline from canonical `evidence/*.yaml` to SQLite/D1-compatible state.

## Command

```bash
python scripts/index-evidence.py
```

By default the local projection is written to `.artifacts/evidence.db`. A different target can be supplied with `--database`.

## Rebuild semantics

The indexer does a full rebuild rather than incremental mutation:

1. create a temporary database;
2. apply all SQL migrations in filename order;
3. read canonical YAML files in deterministic filename order;
4. project each record and its stage/condition mappings inside a transaction;
5. close the completed database;
6. atomically replace the requested local target.

A failed rebuild removes the temporary database and leaves an existing target untouched. Because every rebuild starts empty, removed YAML records cannot survive as stale database rows.

## Determinism

`check-evidence-indexer.py` independently rebuilds the projection twice, compares a canonical logical snapshot of every projected table, rebuilds an existing target again, and verifies the logical state is unchanged.

The invariant is:

```text
same canonical YAML + same migrations = same logical projection
```

The check intentionally compares logical table state rather than SQLite file bytes; physical database layout is not part of the research contract.

## Scope boundary

S3 remains local and CI-only. It does not create or connect to Cloudflare D1, add credentials, publish a database artifact, expose an API, or change the website. Production synchronization belongs to S4.
