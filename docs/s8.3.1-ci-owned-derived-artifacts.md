# S8.3.1 — CI-owned derived artifacts

Evidence contributions author canonical research state. Generated projections are owned by Evidence integrity CI.

## Flow

1. Validate canonical model, research-gap, evidence, and claim-mapping inputs.
2. Run `scripts/build-derived-artifacts.py`.
3. On same-repository pull requests, commit only known generated paths when they changed.
4. Push that commit to the pull-request head branch.
5. The resulting workflow run regenerates the projections and must observe a clean tree.

Fork pull requests remain read-only: generation runs for verification, but CI does not push to a contributor fork.

## Acceptance test

A contribution containing only canonical evidence and evidence-to-claim mappings should be enough to open a pull request. The first Evidence integrity run may add one generated-artifact commit. The subsequent run must be clean and green without contributor intervention.
