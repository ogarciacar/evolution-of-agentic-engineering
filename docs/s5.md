# S5 — Evidence read API

S5 makes the D1 evidence projection queryable without changing the canonical evidence-authoring model.

## Boundary

GitHub YAML remains canonical. D1 remains a disposable projection. This API is read-only: it contains no mutation routes and does not author evidence.

## Endpoints

### `GET /api/evidence`

Returns evidence ordered newest first. Optional filters are combined with AND:

- `stage=Apparition|Mutation|Selection|Cooperation|Specialization`
- `condition=Context|Execution|Verification|Coordination|Observability|Economics|Learning`
- `verdict=SUPPORTS|REFINES|CONTRADICTS|INCONCLUSIVE`
- `producer=<exact producer>`
- `from=YYYY-MM-DD`
- `to=YYYY-MM-DD`

The first slice is deliberately bounded to 100 records. Pagination is deferred until the corpus needs it.

Example:

`/api/evidence?stage=Selection&condition=Verification&verdict=SUPPORTS`

### `GET /api/evidence/:id`

Returns one evidence record by the deterministic ID derived from its YAML filename.

Example:

`/api/evidence/2026-09-03-cursor-pstack`

## Runtime

Only `/api/*` is routed Worker-first. Existing static assets remain asset-first and therefore do not incur a Worker invocation just because the API exists.

The Worker uses the `EVIDENCE_DB` D1 binding and prepared statements with bound parameters. There are no D1 writes in the Worker.

## Preview note

The current Wrangler configuration binds the same D1 database in deployments. S5 performs reads only, so a preview cannot mutate production evidence. If future preview work requires writes or isolated data, introduce a separate preview D1 environment before adding those capabilities.

## Out of scope

- D1 writes from the public Worker
- website redesign or dynamic evidence UI
- R2
- authentication
- full-text or semantic search
- pagination beyond the initial bounded corpus
