# S7.2 — Evidence → claim mapping

S7.2 connects canonical evidence to canonical model claims without deriving a claim-level conclusion yet.

## Contract

Each evidence record declares one or more explicit claim relationships:

```yaml
claims:
  - id: C03
    relationship: REFINES
```

`relationship` uses the same controlled vocabulary as evidence-level model implications: `SUPPORTS`, `REFINES`, `CONTRADICTS`, or `INCONCLUSIVE`.

## Invariants

- Claim relationships are explicit research assertions; stage mapping never implies a claim relationship.
- Every referenced claim ID must exist in `model/claims.yaml`.
- Duplicate claim IDs within one evidence record are invalid.
- D1 remains a disposable projection. Claim mappings must be fully reconstructible from GitHub YAML.
- S7.2 does not calculate or publish an aggregate verdict for a model claim.

## Projection

D1 stores relationships in `evidence_claims(evidence_id, claim_id, relationship)`. The read API returns them as the evidence record's `claims` array.

Existing incorporated evidence is mapped explicitly as part of this slice. These mappings encode which proposition each record bears on; they do not change the source observations or the model claims themselves.
