# S7.2 — Evidence → claim mapping

Evidence records connect canonical evidence to canonical model claims without deriving a claim-level conclusion themselves.

## Contract

Each `evidence/*.yaml` record owns its explicit claim relationships:

```yaml
claims:
  - id: C02
    relationship: REFINES
```

`relationship` uses the same controlled vocabulary as evidence-level model implications: `SUPPORTS`, `REFINES`, `CONTRADICTS`, or `INCONCLUSIVE`.

Keeping the relationship with the evidence record makes the evidence artifact self-contained: source-grounded observations, model mapping, claim relationships, interpretation, boundaries, and verdict travel together and remain reviewable in one place. Git history preserves earlier assessments as the model evolves.

## Invariants

- Claim relationships are explicit research assertions; stage mapping never implies a claim relationship.
- Every incorporated evidence record must contain a non-empty `claims` list.
- Every referenced claim ID must exist in the canonical model.
- An evidence record can reference a claim at most once.
- D1 remains a disposable projection. Claim relationships must be fully reconstructible from `evidence/*.yaml`.
- Claim mapping does not calculate or publish an aggregate verdict for a model claim.

## Projection

D1 stores relationships in `evidence_claims(projection_id, evidence_id, claim_id, relationship)`. The read API returns them as the evidence record's `claims` array.

The projection preserves explicit relationships declared by the evidence record; it does not infer relationships from stage or condition mappings.
