# S7.2 — Evidence → claim mapping

S7.2 connects canonical evidence to canonical model claims without deriving a claim-level conclusion yet.

## Contract

`model/evidence-claims.yaml` is the canonical relationship ledger. It explicitly maps an incorporated evidence ID to one or more model claims:

```yaml
mappings:
  2026-09-03-example:
    - id: C02
      relationship: REFINES
```

`relationship` uses the same controlled vocabulary as evidence-level model implications: `SUPPORTS`, `REFINES`, `CONTRADICTS`, or `INCONCLUSIVE`.

The mapping is intentionally separate from `evidence/*.yaml`. Evidence records preserve observations and their source-level interpretation; the ledger records how the current model reads that evidence against claims that can themselves evolve.

## Invariants

- Claim relationships are explicit research assertions; stage mapping never implies a claim relationship.
- Every incorporated evidence record must have an explicit mapping.
- Every referenced evidence ID and claim ID must exist in the canonical corpus.
- An evidence record can reference a claim at most once.
- D1 remains a disposable projection. Claim mappings must be fully reconstructible from GitHub.
- S7.2 does not calculate or publish an aggregate verdict for a model claim.

## Projection

D1 stores relationships in `evidence_claims(evidence_id, claim_id, relationship)`. The read API returns them as the evidence record's `claims` array.

The initial ledger maps all incorporated evidence explicitly. These mappings encode which proposition each record bears on; they do not change source observations or the model claims themselves.
