# S2 — D1 evidence projection

## Goal

Define a queryable, lossless, SQLite/D1-compatible representation of the canonical YAML evidence corpus while preserving GitHub as the only source of truth.

## Acceptance

S2 is complete when:

- the migration creates the evidence, stage, and condition projection tables;
- every current canonical YAML record can be represented by that schema;
- evidence identity is derived from the YAML filename;
- source metadata, presentation, observations, scale, mapping, interpretation, model implication, limitations, open question, and assessment are preserved in the projection;
- stage, condition, producer, date, and verdict queries have explicit indexes where appropriate;
- foreign keys and controlled vocabularies are enforced;
- CI verifies the projection contract using an in-memory SQLite database;
- no Cloudflare infrastructure, persistent database, API, R2 storage, or website behavior is introduced.

## Next slice

S3 implements the deterministic YAML → projection indexer and proves that a database can be rebuilt idempotently from the canonical corpus.
