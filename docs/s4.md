# S4 — Cloudflare D1 synchronization

## Goal

Make the remote Cloudflare D1 evidence projection converge to the canonical evidence corpus on `main` without making D1 an authoring surface or a website dependency.

## Production invariant

> After a successful synchronization for a commit on `main`, remote D1 represents the canonical evidence corpus from that commit.

The synchronization is a full replacement of projected evidence rows inside a transaction. This preserves the S3 rebuild model: removed YAML records disappear, changed records replace their previous projection, and repeated synchronization converges to the same logical state.

## Bootstrap required once

S4 deliberately does not create Cloudflare account resources from CI. Create the production database once:

```bash
npx wrangler@4 d1 create agentic-engineering-evidence --location weur
```

Cloudflare returns a database UUID. Replace `REPLACE_WITH_D1_DATABASE_ID` in `wrangler.jsonc` with that UUID before merging S4.

Configure the GitHub `production` environment with these secrets:

- `CLOUDFLARE_API_TOKEN` — scoped for the repository's D1 operations.
- `CLOUDFLARE_ACCOUNT_ID` — the Cloudflare account containing the database.

Wrangler requires an API token and account ID in non-interactive CI. The workflow uses the database name, rather than the binding name, for migrations and execution to reduce the chance of targeting the wrong resource.

## Synchronization flow

On relevant pushes to `main`, `.github/workflows/sync-evidence-d1.yml`:

1. validates canonical evidence;
2. exports deterministic SQL from YAML;
3. applies outstanding D1 migrations remotely;
4. executes the synchronization SQL remotely;
5. verifies the remote evidence row count equals the canonical YAML count.

The workflow can also be run manually with `workflow_dispatch` after initial bootstrap.

## Safety

Pull requests never write to production D1. PR CI only verifies that the generated synchronization SQL recreates exactly the same logical projection as the S3 indexer using ephemeral SQLite databases.

The production workflow uses GitHub's `production` environment, read-only repository permissions, serialized synchronization, and Cloudflare credentials stored only as GitHub secrets.

## Scope boundary

S4 synchronizes data but does not make the public website depend on D1. There is no public Evidence API, Worker query endpoint, R2 dependency, or UI change. Reading/querying production evidence belongs to S5.
