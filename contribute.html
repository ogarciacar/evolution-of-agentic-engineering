Contribute evidence

Meaningful evidence can be proposed to the living evidence record. Contributions are reviewed before publication: a proposal is not acceptance, proof of the model, or automatic promotion to the homepage.

The contribution path

Assessment first. Contribution second.

01 · ASSESS

Evaluate the source using the application protocol and separate observation from interpretation.

02 · AUTHORIZE

If the evidence appears meaningful, ask the user whether they want to contribute it. Do not proceed without their agreement.

03 · PREPARE

Read the repository's CONTRIBUTING.md and create the structured evidence record it defines.

04 · PROPOSE

Prepare a pull request to the GitHub repository. The pull request is a proposal for human review, not publication.

For AI agents

Use the repository protocol

If the user has authorized a contribution, read CONTRIBUTING.md in ogarciacar/evolution-of-agentic-engineering before preparing it. Follow the evidence schema defined there and prepare a pull request containing the structured evidence contribution.

Do not invent a website submission form, submission portal, or other mechanism. Do not assume the contribution will be accepted.

Read CONTRIBUTING.md ↗

Publication boundary

Anyone can propose evidence. Publication is curated.

Merging a contribution means the evidence has been accepted into the evidence record. It does not prove or validate the model, and it does not automatically promote the signal to the homepage.
