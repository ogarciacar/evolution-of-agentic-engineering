Signals worth incorporating

August 31, 2026 · Infobip

Context becomes an engineered workflow

SelectionContextExecutionVerificationLearning
Evidence boundary: Practitioner workflow; comparative effectiveness remains unmeasured.
OBSERVED

Infobip's AI research team reports a four-phase workflow for agent-assisted development: research, planning, task definition, and implementation. Human effort is front-loaded and delegation increases as artifacts mature.

Context management is treated as the central concern. The workflow applies four recurring strategies—write, select, compress, and isolate—to reduce context-related failure modes across phases.

The authors report from practitioner experience that errors in upstream research and planning can compound in later phases, while correcting generated code can introduce bloat and fragility; this motivates earlier human review.

Research and planning produce validated artifacts before implementation. Tasks carry goals, dependencies, relevant code paths, acceptance criteria, and validation methods, and are intended to be executable in fresh agent sessions.

The workflow externalizes durable state into artifacts such as Git, task state, and logs so work can be reconstructed across sessions rather than depending on conversational history alone.

The authors identify the absence of established metrics for workflow effectiveness as an open problem; the paper does not provide a controlled comparison showing that the workflow outperforms unstructured delegation.

INTERPRETATION

Selection may favor environments that make context bounded, validated, compressible and reconstructable rather than simply maximizing available context. Durable state is externalized so fresh sessions can reconstruct sufficient state, while human attention is concentrated where upstream errors have the greatest propagation cost.

MODEL IMPLICATION

SUPPORTS. Context, Execution and Verification appear as engineered environmental conditions. Updating project instructions in response to recurring agent mistakes provides an emerging Learning signal, while the paper explicitly leaves workflow effectiveness as an open measurement problem.

August 27, 2026 · Uber

The software factory selects for complete managed capabilities

Selection → Cooperation / SpecializationContextExecutionVerificationCoordinationObservabilityEconomics
Scale signal: More than 70% of PRs attributed to local or cloud agents; 3,600+ agent skills; 30,000+ skill executions/day. Uber reports 7× weekly active users and 9.4× weekly agentic requests from February to August 2026.
OBSERVED

Uber reports that more than 70% of its pull requests are attributed to local or cloud agents, that engineers have created more than 3,600 agent skills, and that those skills execute more than 30,000 times per day. Managed agents perform code review, CI self-healing, end-to-end changes with visual validation, alert triage, debugging, and code maintenance.

From February to August 2026, Uber reports a sevenfold increase in weekly active users and a 9.4-fold increase in weekly agentic requests. Holding one model fixed, it reports that cost per 1,000 model requests fell nearly 34% from its peak and cost per session fell 52% from its June peak.

Uber decomposes total spend into adoption, engagement, turns, requests, tokens, and token price. For each managed agent it also tracks an outcome-denominated cost, a quality signal such as revert rate, F1, or mean time to recovery, and delivered volume.

Model selection uses benchmarks assembled from each managed agent's real work and evaluates cost per completed task, output quality, and reliability. Uber reports using an AI Context Graph, tool search, CLI-resolved tool calls, prompt caching, standardized defaults, and code mode to reduce context-search and tool-use overhead.

Uber reports that a primary model can decompose and evaluate work while lower-cost subagents execute bounded tasks. Live cost counters and a session-analysis dashboard expose spend drivers and identify 16 classes of session anti-pattern, each paired with financial impact and a targeted remediation.

INTERPRETATION

Fitness is being evaluated at the level of workload + model + context + tools + runtime + verification + reliability + cost, rather than model quality alone. Economics becomes an explicit selection mechanism, while bounded delegation and stable task-specific managed agents create Cooperation and operational Specialization signals.

MODEL IMPLICATION

REFINES. Operational specialization can appear during Selection while Cooperation is still developing. The source does not establish that repeated Cooperation caused those specializations, so it weakens a strictly sequential reading without falsifying the proposed sequence.

June 16, 2026 · Anthropic

Human expertise stays load-bearing while the agent executes

ApparitionSelectionContextExecutionVerificationObservability
Scale signal: Approximately 400,000 interactive sessions from approximately 235,000 users over seven months, the largest observation in this record. The unit of observation is a single human-steered session; headless and programmatic usage is excluded and no concurrency figure is reported.
OBSERVED

Anthropic analyzed approximately 400,000 interactive Claude Code sessions from approximately 235,000 users between October 2025 and April 2026, using privacy-preserving classifiers built on Claude Sonnet 4.6.

Users make approximately 70% of planning decisions and Claude makes approximately 80% of execution decisions. A typical session runs about four turns, each prompt triggers about 10 Claude actions and occasionally more than 100, and Claude reads files, edits code, runs commands, and writes about 2,400 words of output per turn.

Novice sessions average about 5 Claude actions and 600 words per prompt while expert sessions average about 12 actions and 3,200 words. Anthropic reports the difference at p<0.001 and states that it remains significant when controlling for work mode, task value, month, occupation, and model family.

Verified success, measured from git commits and pull requests matching the work, passing test suites, and explicit confirmation, is 15% for novices and 28-33% for intermediate and expert users. At least partial success is 77% versus 91-92%. Most of the gain occurs from novice to intermediate and then flattens. Novices abandon troubled sessions at 19% against 5-7% for intermediate through expert users.

Domain knowledge matters more than coding background: non-software occupations reach 29% verified success on coding sessions against 34% for software occupations, and all ten largest occupation groups fall within seven percentage points.

Between October 2025 and April 2026 debugging fell from 33% to 19% of work, operating software rose from 14% to 21%, writing and analysis roughly doubled from about 10% to about 20%, and the estimated value of the average session rose 27%.

Anthropic excludes headless sessions run as a single prompt via the CLI and describes the excluded non-interactive usage as a substantial share of activity. It states that it cannot measure whether code written in a session is actually used or discarded thereafter, that classifiers remain challenging to validate at scale, that task value estimates are coarse, and that about 30% of sessions lack a classifiable occupation signal.

INTERPRETATION

Apparition is documented at scale rather than asserted: the agent interprets intent, reads files, edits code, runs commands, and works through errors across chains of about 10 and occasionally more than 100 actions. The Selection content is that the variable separating useful outcomes from abandoned ones is the quality of human direction rather than the agent, and that this gradient did not decay across seven months of model change. Much of the context the agent needs still arrives through the operator, and the verification signal the study itself relies on is git and test evidence.

MODEL IMPLICATION

REFINES. The model places human attention in the denominator of agentic-system fitness, as a cost to be reduced. This evidence is consistent with human expertise also acting as an input that raises useful outcome: experts cause roughly double the agent activity per prompt and land verifiable results about twice as often, and the gap persists across model families and months. It also refines the Context condition, since a substantial share of the knowledge an agent uses is supplied by the operator rather than acquired by the agent. This does not falsify the Selection hypothesis; it suggests the human-dependency ceiling described by the 1K forcing function may bind through planning and context supply, not only through verification.

June 3, 2026 · Spotify

Coding stops being the constraint

Selection → CooperationExecutionVerificationCoordinationEconomics
Scale signal: 2.5M+ automated maintenance PRs merged; vast majority auto-merged without a human. Honk schedules many agent sessions concurrently in Kubernetes. AI-driven velocity produced 76% more PRs to review.
OBSERVED

Spotify reports operating Honk coding-agent sessions in Kubernetes with trusted tools and CI verification, integrated with fleet orchestration.

Spotify reports more than 2.5 million automated maintenance pull requests merged, with the vast majority auto-merged without human intervention.

Spotify reports a Java migration across backend services completed in three days and describes AI-driven velocity creating 76% more pull requests to review.

INTERPRETATION

Once code production becomes cheap, verification, orchestration and human decision-making become more visible constraints. Existing platform standardization appears to increase agent fitness.

MODEL IMPLICATION

SUPPORTS. Strong support for Selection conditions and an emerging Cooperation transition. It also suggests human attention belongs explicitly in the fitness function.

May 20, 2026 · Google Cloud

Long-running agents require a runtime

Mutation → SelectionExecutionObservabilityLearning
Scale signal: Agent workflows lasting hours or days; Google describes reliability and efficient production management as the emerging operational problem.
OBSERVED

Google describes agent workflows lasting hours or days and reliability and efficient production management as an emerging operational problem.

Google introduced Agent Executor for execution, resumption, and distributed deployment, using event logs and snapshots so long-running agents can survive outages and human-in-the-loop interruptions.

INTERPRETATION

Reliability mechanisms that can be tolerated as ad hoc behavior at low scale become infrastructure concerns as autonomy and duration increase.

MODEL IMPLICATION

SUPPORTS. Supports Selection: the environment increasingly determines which agent configurations remain operationally viable, not merely which model performs best.

April 27, 2026 · OpenAI

Human attention becomes the concurrency ceiling

Selection → CooperationCoordinationObservabilityExecutionVerification
Scale signal: Engineers could comfortably supervise only 3–5 Codex sessions at once; Symphony produced a 500% increase in landed PRs on some teams.
OBSERVED

OpenAI reports that engineers could comfortably supervise only three to five Codex sessions at once; beyond that productivity dropped as engineers lost track of work and debugged stalled agents.

Symphony moves coordination to an always-on orchestrator where open tasks receive agents in isolated workspaces and humans review outcomes.

OpenAI reports a 500% increase in landed pull requests on some teams.

INTERPRETATION

Cooperation can begin before rich agent-to-agent collaboration. Independent agents first create a coordination problem; explicit orchestration then allows their work to compose as a system.

MODEL IMPLICATION

REFINES. Refines the Selection → Cooperation boundary: coordination infrastructure may be a mechanism through which Selection produces Cooperation.

February 12, 2026 · Gloaguen et al.

Context files raise cost without significant task-success gains

SelectionContextVerificationEconomics
Scale signal: Results span four model-agent configurations, 300 SWE-bench Lite tasks from 11 repositories, and 138 CTXbench tasks from 12 repositories. All evaluated repositories use Python, and each agent-condition completion was sampled once.
OBSERVED

The authors evaluated Claude Code with Sonnet 4.5, Codex with GPT-5.2 and GPT-5.1 mini, and Qwen Code with Qwen3-30B-coder across SWE-bench Lite and a new CTXbench benchmark. SWE-bench Lite contains 300 tasks from 11 popular Python repositories; CTXbench contains 138 tasks from 12 recent, less popular Python repositories with developer-committed context files.

LLM-generated context files changed average resolution rate by -0.5% on SWE-bench and -2% on CTXbench. Neither difference was statistically significant. They increased the average number of agent steps in every setting and raised average inference cost by 20% and 23%, respectively; the cost increases were statistically significant.

On CTXbench, developer-provided context files improved average resolution rate by 2.4%, which was not statistically significant at p=0.21. They significantly outperformed LLM-generated files at p=0.038, while adding an average of 3.34 agent steps and increasing cost by as much as 19%.

Trace analysis found that agents generally followed context-file instructions. With context files present, agents ran more tests, performed more code-quality checks, explored more files, and used named repository-specific tools more often, but these behavioral changes did not produce a significant overall improvement in resolution rate.

Repository overviews did not meaningfully reduce the number of steps before agents interacted with a file modified by the reference patch. For GPT-5.1 mini, context files significantly increased those steps, including repeated attempts to find and read a context file already included in the agent's context.

In an ablation where the authors removed other documentation from CTXbench repositories, LLM-generated context files improved resolution rate by 2.7% on average and consistently outperformed developer-provided files. The authors interpret this result as evidence that generated context files are often redundant with documentation already present in a repository.

INTERPRETATION

Context availability is not equivalent to context fitness. Repository files can successfully steer agents toward more testing, exploration, quality checks and specialized tools while still increasing cost without improving test-verified outcomes. Whether context is useful depends on its relevance and novelty relative to knowledge already available in the repository. This also separates verification activity from verification value: performing more checks did not by itself raise task-resolution success.

MODEL IMPLICATION

REFINES. The results refine Selection by showing that adding a commonly recommended environmental artifact can reduce rather than improve agent fitness. The environment still measurably shapes behavior and Economics, but Selection must evaluate context quality, redundancy and outcome impact rather than treating additional context as inherently beneficial. Instruction following and increased verification activity are insufficient proxies for useful outcome.

January 28, 2026 · Lulla et al.

Repository instructions reduce agent runtime and output tokens

SelectionContextEconomics
Scale signal: A paired comparison across 124 pull-request tasks from 10 repositories. The sample was limited to merged, code-only changes of at most 100 changed lines and five modified files, run with one Codex model and one qualifying root AGENTS.md file per repository.
OBSERVED

The authors studied 124 merged pull-request tasks from 10 repositories using OpenAI Codex with gpt-5.2-codex. Each task was run against the same pre-merge repository snapshot under paired conditions that differed only in whether the root AGENTS.md file was present.

With AGENTS.md present, median wall-clock completion time decreased from 98.57 seconds to 70.34 seconds, a 28.64% reduction. Mean completion time decreased from 162.94 seconds to 129.91 seconds, a 20.27% reduction. The wall-clock difference was statistically significant under a Wilcoxon signed-rank test at p<0.05.

Median output-token consumption decreased from 2,925 to 2,440 tokens, a 16.58% reduction. Mean output-token consumption decreased from 5,744.81 to 4,591.46 tokens, a 20.08% reduction. The output-token difference was also statistically significant at p<0.05.

Median input tokens, cached input tokens, and total tokens were slightly higher with AGENTS.md, and the paper does not mark differences in those metrics as statistically significant. The authors interpret the output-token result as being influenced by a small number of very high-cost runs rather than a uniform reduction across all tasks.

The experiments ran in fresh, isolated Docker environments without reused task state. The study did not comprehensively evaluate semantic correctness or functional equivalence; a manual sanity check of 50 randomly sampled tasks established only that outputs were non-empty, non-trivial, and consistent with the intended task rather than aborted or random changes.

When a pull request lacked a usable natural-language description, the authors generated a GitHub-issue-style task statement with a local language model given the human-authored pull-request diff and the pre-merge repository tree. The same generated task statement was used in both paired conditions.

INTERPRETATION

A version-controlled repository instruction file is an environmental condition rather than a model change. Holding the task, repository state and agent configuration constant while adding that context changed two operational costs: completion time and generated output. This makes Context an experimentally varied part of agent fitness and connects it to Economics, while the mixed token results caution against treating additional context as a uniform reduction in resource use.

MODEL IMPLICATION

SUPPORTS. The paired results support the Selection proposition that engineering environments can measurably affect agent operation. In this bounded study, repository-level instructions were associated with lower runtime and output generation cost even though the model and task were held constant. The evidence supports an operational effect on the fitness denominator; because correctness was not evaluated, it does not establish improved useful outcome or overall agentic-system fitness.

What we have not observed

Absence matters too

The current evidence is strongest for Selection and increasingly informative at its boundaries with Cooperation and operational Specialization.

Open evidence gaps
  • No accepted source establishes operation of 1,000 concurrent coding agents. 1K remains a forcing function, not an industry benchmark.
  • Uber provides an operational Specialization signal, but does not establish that repeated Cooperation caused specialization.
  • Comparable compute-cost evidence remains sparse outside a small number of sources.
  • Learning loops remain less documented than execution and coordination infrastructure.
  • Contradictory evidence should be added here with the same prominence as supporting evidence when it appears.
