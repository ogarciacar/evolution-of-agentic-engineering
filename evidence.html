Signals worth incorporating

August 31, 2026 · Infobip

Context becomes an engineered workflow

SelectionContextExecutionVerificationLearning
Evidence boundary: practitioner workflow; comparative effectiveness remains unmeasured.
OBSERVED

Infobip's AI research team reports a four-phase workflow: research, planning, task definition and implementation. Human effort is front-loaded and delegation increases as validated artifacts mature. Context is managed through write, select, compress and isolate; tasks carry goals, dependencies, code paths, acceptance criteria and validation methods for execution in fresh sessions.

INTERPRETATION

Selection may favor environments that make context bounded, validated, compressible and reconstructable rather than simply maximizing available context. Durable state is externalized so fresh sessions can reconstruct sufficient state, while human attention is concentrated where upstream errors have the greatest propagation cost.

MODEL IMPLICATION

SUPPORTS. Context, Execution and Verification appear as engineered environmental conditions. Updating project instructions in response to recurring agent mistakes provides an emerging Learning signal, while the paper explicitly leaves workflow effectiveness as an open measurement problem.

August 27, 2026 · Uber

The software factory selects for complete managed capabilities

Selection → Cooperation / SpecializationContextExecutionVerificationCoordinationObservabilityEconomics
Scale signal: more than 70% of PRs attributed to local or cloud agents; 3,600+ agent skills; 30,000+ skill executions/day. Uber reports 7× weekly active users and 9.4× weekly agentic requests from February to August 2026.
OBSERVED

Uber reports managed agents for code review, CI self-healing, end-to-end changes with visual validation, alert triage, debugging and maintenance. Each managed agent is evaluated using outcome-denominated cost, a quality signal such as revert rate, F1 or MTTR, and delivered volume. Primary models can decompose and evaluate work while lower-cost subagents execute bounded tasks.

INTERPRETATION

Fitness is being evaluated at the level of workload + model + context + tools + runtime + verification + reliability + cost, rather than model quality alone. Economics becomes an explicit selection mechanism, while bounded delegation and stable task-specific managed agents create Cooperation and operational Specialization signals.

MODEL IMPLICATION

REFINES. Operational specialization can appear during Selection while Cooperation is still developing. The source does not establish that repeated Cooperation caused those specializations, so it weakens a strictly sequential reading without falsifying the proposed sequence.

June 3, 2026 · Spotify Engineering

Coding stops being the constraint

Selection → CooperationExecutionVerificationCoordinationEconomics
Scale signal: 2.5M+ automated maintenance PRs merged; vast majority auto-merged without a human. Honk schedules many agent sessions concurrently in Kubernetes. AI-driven velocity produced 76% more PRs to review.
OBSERVED

Spotify combines Fleetshift orchestration with Honk, a Claude-based coding agent running in Kubernetes pods with trusted tools and CI verification. A recent Java migration across backend services took three days.

INTERPRETATION

Once code production becomes cheap, verification, orchestration and human decision-making become more visible constraints. Existing platform standardization appears to increase agent fitness.

MODEL IMPLICATION

Strong support for Selection conditions and an emerging Cooperation transition. It also suggests human attention belongs explicitly in the fitness function.

May 20, 2026 · Google Cloud

Long-running agents require a runtime

Mutation → SelectionExecutionObservabilityLearning
Scale signal: agent workflows lasting hours or days; Google describes reliability and efficient production management as the emerging operational problem.
OBSERVED

Google introduced Agent Executor for execution, resumption and distributed deployment, using event logs and snapshots so long-running agents can survive outages and human-in-the-loop interruptions.

INTERPRETATION

Reliability mechanisms that can be tolerated as ad hoc behavior at low scale become infrastructure concerns as autonomy and duration increase.

MODEL IMPLICATION

Supports Selection: the environment increasingly determines which agent configurations remain operationally viable, not merely which model performs best.

April 27, 2026 · OpenAI

Human attention becomes the concurrency ceiling

Selection → CooperationCoordinationObservabilityExecutionVerification
Scale signal: engineers could comfortably supervise only 3–5 Codex sessions at once; Symphony produced a 500% increase in landed PRs on some teams.
OBSERVED

OpenAI reports productivity dropping beyond three to five simultaneously supervised sessions because engineers lost track of work and had to debug stalled agents. Symphony moves coordination to an always-on orchestrator: open tasks receive agents in isolated workspaces and humans review outcomes.

INTERPRETATION

Cooperation can begin before rich agent-to-agent collaboration. Independent agents first create a coordination problem; explicit orchestration then allows their work to compose as a system.

MODEL IMPLICATION

Refines the Selection → Cooperation boundary: coordination infrastructure may be a mechanism through which Selection produces Cooperation.

April 24, 2026 · Cursor

The interface reorganizes around many agents

Selection → CooperationExecutionCoordinationContextVerification
Scale signal: Cursor publicly supports many parallel agents and fleets of async subagents; no credible fleet-wide concurrency number is published in these sources.
OBSERVED

Cursor's Agents Window runs many agents across repositories and environments. Multitask decomposes work into async subagents, while worktrees isolate concurrent changes and parallel plans preserve task dependencies.

INTERPRETATION

The product surface itself is shifting from a single conversational agent toward supervision, isolation and composition of parallel work.

MODEL IMPLICATION

Supports an emerging Cooperation transition, while the absence of public scale numbers is a useful reminder not to equate product capability with demonstrated fleet-scale operation.

What we have not observed

Absence matters too

The current evidence is strongest for Selection and increasingly informative at its boundaries with Cooperation and operational Specialization.

Open evidence gaps
  • No accepted source establishes operation of 1,000 concurrent coding agents. 1K remains a forcing function, not an industry benchmark.
  • Uber provides an operational Specialization signal, but does not establish that repeated Cooperation caused specialization.
  • Comparable compute-cost evidence remains sparse outside a small number of sources.
  • Learning loops remain less documented than execution and coordination infrastructure.
  • Contradictory evidence should be added here with the same prominence as supporting evidence when it appears.
